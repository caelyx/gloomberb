Why SQLite Uses Bytecode

By Jane Doe · 12 min read

SQLite compiles every SQL statement into a program for a small virtual machine. The program is a list of instructions, each doing one simple thing, and the virtual machine runs them one after another until the statement is done.

Most other databases compile SQL into a tree of objects instead. Each node in the tree knows how to produce rows, and the root pulls rows from its children. That design is flexible, but it is much harder to see what the database is actually going to do.

Reading the plan

Because the bytecode is a flat list, you can print it with EXPLAIN and read it from top to bottom. Every loop, every comparison, and every jump is visible, and the output is the same on every machine that runs the same version of SQLite.

A flat program is easier to reason about than a tree of cooperating objects.

  • The program can be paused after any instruction & resumed later.
  • Progress callbacks are cheap, because the loop already counts steps.

None of this makes SQLite faster than a tree-walking engine on its own. What it buys is predictability: the same statement produces the same program, and the program is small enough to read.
